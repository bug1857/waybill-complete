Greedy vs Branch & Bound

Greedy chooses the closest unvisited stop. Branch & Bound starts with a feasible tour, explores partial tours by lower bound, and prunes branches that cannot improve it. A budget-limited result may remain unproven.

Project topic & generated report

Courier Delivery Route Optimization System

Required DAA concepts: TSP, Greedy, and Branch & Bound. The report below records the active solution and any comparison performed on the same input.

Problem and algorithm design

Input: a depot, customer locations, and a directed integer distance matrix. Output: a closed tour visiting every customer exactly once, its total distance, feasibility, and solve status. The objective is to minimize the sum of tour edges.

Greedy nearest neighbour: scan the unvisited customers for the cheapest next edge, with node-index tie breaking. This implementation takes O(n²) selection work and O(n) extra storage. It produces a feasible tour without proving optimality.

Branch & Bound: keep partial tours in a lower-bound priority queue, branch to each remaining customer, and prune using an admissible minimum incoming/outgoing edge bound. Search can grow factorially in the worst case. A finished proof establishes optimality for this input matrix; a time, node, or memory limit preserves a feasible incumbent with its remaining lower bound.

Optional extensions: Held–Karp validation, road geometry from OSRM, and CVRPTW fleet constraints. Road and offline distance models are identified in each result.
